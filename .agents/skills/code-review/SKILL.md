# Code review

1. Leia o diff e o contexto dos arquivos afetados.
2. Priorize bugs reais, regressões, falhas de autorização, vazamento de dados e problemas de integridade.
3. Verifique tipos, estados de UI, fronteiras server/client, tratamento de erros e acessibilidade.
4. Avalie performance com base em evidências, sem micro-otimizações especulativas.
5. Para cada achado, informe severidade, arquivo/trecho, cenário de falha e correção sugerida.
6. Não altere os arquivos durante a revisão, salvo se houver autorização explícita separada.
7. Termine com veredito: aprovado, aprovado com ressalvas ou bloqueado, justificando.
